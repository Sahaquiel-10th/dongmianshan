# 东面山官网

Next.js 16 + React 19 + Prisma。正式数据库继续使用 MySQL，保留原有管理员会话与权限。

## 日常运营：按官网页面编辑

后台首页 `/admin` 现在按官网导航排列：首页、品牌、产品、护理指导、官方购买。名称直接读取官网导航配置，每个入口显示当前实际标题与配图；进入后按官网从上到下列出区域。原 `/admin/sections` 入口会转到这个页面地图，不再把所有数据库板块平铺给运营人员。

- 修改区域标题或图片：选择官网页面 → 找到当前画面标题 → “编辑这里的文案与图片”。
- 修改产品或原料卡片：在同一页面下方直接点对应卡片的编辑按钮，进入它实际引用的产品或文章资料；编辑页会标明同步到哪些位置。文章封面用于详情页，栏目卡片使用标题与摘要。
- 直接在官网编辑：员工登录后打开官网，海报、产品、栏目说明与卡片默认显示“编辑此处”，进入对应表单后可返回官网原位置。顶部员工工具条可切换“预览访客效果 / 显示编辑按钮”；未登录访客看不到这些工具，`?edit=1` 本身不授予权限。
- 文章末尾与文章卡片下方有“编辑文章 / 删除文章”；删除前需确认，随后从官网所有引用位置下架，15 天内可在后台回收站恢复。删除当前文章后自动回到所属栏目。
- 栏目列表的最后一项是“＋新增文章”，空栏目也可直接添加，自动选好栏目。可保存草稿，或选择“发布 / 官网展示”后点“保存并返回官网”。从官网进入的文章编辑页同样支持保存后返回。
- 导航、Logo、页脚与共用按钮文字：进入“导航、页脚与共用文字”，每组标明对应位置，导航与页脚有当前文字示意。保存后使用同一份资料的位置同步更新。
- 新增栏目文章：在对应栏目点新增，会自动带入该栏目；全部文章列表也支持按官网栏目和标题筛选。
- 文章正文放在关联设置前面；关联区可展开，支持按标题查找、查看已选项和移除关联，搜索不会清空已有选择。
- 单张海报与多张海报使用不同字段时，表单只显示当前真正生效的字段。新增第二张会保留原海报，删除最后一张会同时切为草稿，避免旧单张设置重新展示。

本轮只调整编辑入口、命名与定位，不改现有内容、产品和文章关系或数据库结构。日常保存发布仍不需要重新部署。

## 本地预览

```sh
npm ci
npm run local:setup
npm run dev -- --port 3100
```

打开 http://localhost:3100 。后台在 `/admin/login`，本地测试账号和随机密码见未提交的 `.env.local`。

`local:setup` 从正式 schema 生成仅用于本机的 SQLite schema，建立 `prisma/dev.db` 并填充示例，不改变正式 MySQL schema。重复执行不覆盖已修改、下架或软删除的内容。已有 `.env.local` 保留，请勿将正式数据库配置与本地预览混用。

导航结构保留四个主入口，导航名称、品牌说明、页脚和各类固定栏目文案均可在“全站文案”修改。页面都有共享导航；面包屑最多四级：首页 / 护理指导 / 栏目 / 词条。原肌肤测试是无结果逻辑的占位表单，旧入口保留 308 跳转至护理指导。

产品的基础介绍、使用方法、特性、原料成分、功能功效分别对应详情页五个区域。购买链接同步用于产品详情与官方购买页；未填购买链接时不展示空链接。

关联知识用标题勾选。文章可关联其他文章及产品，产品可关联知识；官网显示主动关联与被关联，形成双向浏览。关联只展示已发布且未删除的内容。取消一条由其他内容建立的关联时，需到建立该关联的来源内容编辑。

示例路径：人群认知 / 35 岁 → 问题解决 / 晨间出油 → 原料与使用指南 → 产品 → 购买。站内搜索支持标题、标签、摘要和正文匹配，并覆盖会议中的自然语言示例；目前是轻量分词匹配。

示例图片与产品功效、原料介绍均须由品牌补充核实。原料知识关联不代表对应产品已添加该成分。示例标记可在产品/文章编辑页取消，示例本身可修改、下架或软删除。

## 发布与删除

- 产品和官网区块：选择发布状态并保存，官网下次读取即显示；草稿下架，清空字段后不会重新带回默认内容。
- 文章：可保存当前状态，或先进入预览再发布；原有软删除与 15 天回收站保留。
- 区块条目支持排序、删除和恢复。
- 首页、分类页、搜索页及其他区块可分别编辑主图、标题、说明、正文、标签、按钮和条目。

- 初次启用可在后台首页点击“补齐缺失的示例内容”。仅创建缺失记录；已有内容不会被重置，软删除示例也不会被恢复。
- 空栏目正常展示空状态。无效地址或已下架的详情返回 404；数据库连接错误显示加载失败，避免冒充“内容不存在”。
- 旧的场景、证言、测试区块保留在数据库中，本次不再展示于首页，也不删除历史数据。

## 正式 MySQL 部署

使用部署环境自己的 `.env` / 环境变量（参考 `.env.example`），不要上传本地 `.env.local` 或 SQLite 数据库。

```sh
npm ci
npm run build
npm run start
```

`npm run build` 和 `npm start` 现在会自动运行增量准备脚本，仅创建缺表和补齐缺失字段，不删除表或字段，并补齐尚不存在的示例。目前已确认的正式发布方式是服务器拉取 Git、安装依赖、构建后重启 PM2 进程 `dongmianshan`；Git 推送自动部署尚未确认。

字段同步是增量扩展：产品增加 usage/features/ingredients/relatedArticleIds/isExample，文章增加 relatedProductSlugs/isExample，保留已有表和其他字段。部署前按原运维流程备份数据库。`content:seed` 仅用于补齐示例，可选；正式内容足够时可跳过。现有同 slug 文章使用真实 ID 建立新示例关联，不覆盖原文。

`/admin/setup` 可检查新增字段是否就绪。所有写 API 仍需原管理员会话。线上通过 `/api/health` 的版本标识与数据库检查确认发布结果。

## 验证

```sh
npm run check
npm run test:smoke
npm run test:links
npm run test:editability
npm run test:markdown
npm run test:editor
npm run build
```

两个 `test:*` 命令需要已启动的本地预览服务（默认 3100）。`test:smoke` 限制本地地址与 SQLite，包含未授权写入拒绝、五项字段保存、双向关系、草稿和删除过滤、区块发布及示例不复活，并清理测试数据。`test:links` 检查站点地图、页面实际站内链接和旧入口跳转。

`npm run build` 会恢复生成 MySQL 客户端。如需回到本地 SQLite 预览，再运行一次 `npm run local:setup`。

## 图片与全站文案

后台所有图片字段支持直接上传、预览、链接替换与移除。图片最大 8 MB，上传后转为 WebP（最多 2560 像素，GIF 取首帧），存入 MySQL 的 MediaAsset 表，由 `/media/<name>` 提供读取；不依赖代码部署目录，因此重新部署后仍保留。

全站文案入口 `/admin/site-copy` 管理品牌标识、四个导航及子导航名称、页脚、搜索提示、结果模板、文章及产品固定栏目名称、空状态和访问失败提示。保存即发布；品牌名和四个主导航名不可留空，搜索结果模板保留 `{query}` 和 `{count}`。界面布局、路由和后台本身的操作字段不作为官网运营内容编辑。

`test:editability` 验证每类新增编辑项、上传权限、无效图片拦截和不同页面的图片复用；结果保存在忽略提交的 output 目录。

示例补齐优先复用原库三款产品的完整链接。早期版本按不同 slug 新增的三款示例，只有在所有运营字段及关联均与初始示例一致时，才执行一次性归并：原产品和正文不变，知识关联合并到原产品，重复示例保留为草稿，旧示例产品链接跳转到已发布的原产品。已改动、下架或删除的记录不会被自动归并；归并后再次手动发布也会保留。`npm run test:product-seed` 在独立的本地数据库副本验证这些情况，不修改当前预览或正式数据库。

## 部署补丁与依赖检查

2026-10-21 部署日志中的依赖告警已复核：Next.js / @next/env 固定到 16.3.8、sharp 固定到 0.35.5，正文过滤组件固定到兼容服务器 Node 20 的 sanitize-html 2.17.5。正文继续只允许文章排版标签与受限链接属性，并显式丢弃 raw-text 容器的内容；`test:markdown` 覆盖危险 HTML 与正常文章显示。

本轮 `npm audit` 的 critical 项已清零，仍有 Prisma 6 构建工具链的 4 个 high 提示及 sanitize-html 的 1 个 moderate 提示。过滤组件更高版本要求 Node >=22.12，Prisma 的审计修复要求升级到 7；这些未作未经验证的跨版本升级。当前白名单不允许 SVG、meta、表单或事件属性，但不将此记录视为依赖审计完全通过。不要在服务器执行 `npm audit fix --force`；后续升级应在开发环境验证后发布。
